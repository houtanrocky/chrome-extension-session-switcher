Keep multiple accounts signed in on the same site, side by side.

Session Switcher creates named sessions with separate cookies and browser storage, so you can move between work, personal, client, support, and test accounts without repeatedly signing out of your normal browser profile.

GET STARTED
1. Open a login-gated site and click Session Switcher.
2. Create a named session such as Work, Personal, Admin, or Guest.
3. Choose Open new tab or Use this tab, then log in.
4. Create another session and open it beside the first one.

USE IT FOR
• Keeping multiple accounts available on one site
• Comparing different roles and permissions
• Checking whether logout in one session affects another
• Switching between work, personal, client, support, and QA accounts
• Reproducing an account-specific issue without separate browser profiles

FEATURES
• Separate cookie jars for managed tabs
• Namespaced localStorage, sessionStorage, and IndexedDB
• Named and color-coded sessions grouped by site
• Clear Open new tab and Use this tab actions
• Export and import for local session backups
• Chromium support: Chrome, Edge, Brave, Opera, and Arc

WHAT'S NEW IN 0.2.0
• Temporary cookie-rule update failures retry without discarding a live tab's session binding.
• A first-use guide explains how to create two sessions for the same site.
• Session actions have visible labels and the next-session action is clearer.

LIMITATIONS
Sessions are scoped to a site/domain. After a browser restart, reconnect restored tabs before using them. External identity-provider SSO and cross-domain login flows may behave inconsistently. Storage isolation is best effort; this extension is not a security sandbox or a separate browser profile. Managed tabs disable site service-worker registrations, which can affect offline cache and web push. Cookie path handling is approximate.

PRIVACY
Session data and captured cookies stay in local browser extension storage. There is no developer account, analytics, advertising, tracking, or remote session service. Exported backups contain sensitive login data and should be protected. Normal website requests still go to those websites.

See the support link for the changelog and usage notes. When reporting a problem, include the extension version, browser version, site category, steps, and approximate time before failure. Never include cookies, tokens, credentials, or exported backups.
